# Development status

The current implementation adds lazy `FListView`, a fuller `FTextField` and `FForm` contract, rich-text and Markdown renderer boundaries, `FSegmentedControl`, `FToast`, a broader `FIcons` vocabulary, `FDataGrid`, `FTreeView`, floating panels, and FFrame-owned window chrome/manager contracts. Riverpod, Markdown, FFlow, and native window platform boundaries are documented. Shared controls continue to resolve visuals through `FTheme`; applications can use the WPF system with light/dark and normal/compact density switching.

`FDataGrid` currently provides lazy rows, fixed-width columns, client-side comparator sorting, and controlled row selection. It does not implement paging, editing, column resizing, or remote querying. `FTreeView` supports lazy child loading, error callbacks, expansion, selection, and basic arrow-key navigation. Floating panels are in-app overlays. Optional `fframe_window` now supplies a native desktop adapter and Showcase host registrations; OS-level behavior still needs runtime verification on each desktop platform.

The monorepo contains five packages (`fframe`, `fframe_layout`, `fframe_design`, `fframe_wpf`, and optional `fframe_window`) plus two examples. Showcase tests cover lazy construction, input formatting/form validation, grid sorting and keyboard selection, tree loading and keyboard expansion, dialog/popover focus restoration, and a WPF control baseline. Remaining release work includes broader visual state baselines, a host-based screen-reader and keyboard audit, constraint/performance review, API coverage and examples for every exported symbol, native runner builds and multi-window runtime verification on each desktop OS, hosted CI runs, and a release rehearsal. The package compliance helper remains a later ecosystem enhancement.
