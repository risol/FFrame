# Development status

The `fframe` package exposes FFrame-owned composition primitives, layouts, design contracts, app host, and shared controls. Application examples import only FFrame APIs; Flutter Widgets and Material are not part of the app-facing surface. The sole FFrame visual package is `fframe_wpf`; the Showcase uses its WPF style with light/dark and normal/compact density switching. Shared controls consume explicit density overrides, and Select/Popover expose keyboard and semantic activation.

The monorepo currently contains four publishable packages (`fframe`, `fframe_layout`, `fframe_design`, and `fframe_wpf`) plus two examples. The application-facing `fframe` package owns FFrame composition primitives, shared controls, and the app host; `fframe_layout` contains design-system-agnostic desktop layout primitives. On Flutter 3.47.7, `melos analyze` and `melos format` pass across all six projects. Pub dry-run passes for all four packages with no warnings; `fframe` and `fframe_wpf` report hints because Melos links local package overrides. The Windows Showcase release build succeeds.

Remaining 1.0 work includes broad screen-reader and keyboard audits, test coverage for overlay focus/dismissal and control states, intrinsic/constraint performance audits, WPF visual golden coverage across states, complete API documentation, and a release rehearsal. CI defines Windows, macOS, Linux, and Web jobs, but those jobs still need to run in the hosted environment. The package compliance helper is a later ecosystem enhancement. DataGrid, TreeView, floating dock panels, native window chrome, and multi-window management remain explicitly outside 1.0.
